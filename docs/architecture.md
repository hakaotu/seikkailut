# Architecture

As-is description after SEI-1, SEI-45 (voice ranking, pause between parts), SEI-2/5/6 (Matikka port), SEI-46 and SEI-47 (auto-advance in Matikka and Sanat) and SEI-3/7/8 (Sanat port), SEI-49 (Sanat end texts), SEI-4/9/10/48 (Espanja port), SEI-50 to 56 (more Sanat words, five more Espanja topics) and SEI-57 (Espanja topic picker). Intent and history live in `docs/plans/`; the design spec is `docs/design/sei-1.md` (+ `.html`).

## What this is

Seikkailut: one static web app (Finnish UI, `lang="fi"`) meant to hold three children's games, Matikka, Sanat, Espanja, behind a front page. Target device is an iPad in Safari. All three are real games. Hosted on GitHub Pages at https://hakaotu.github.io/seikkailut/ (see Layout).

`originals/` holds the three old standalone HTML games and `vauhti.mp3`. They are reference material: not served, not imported, not modified. Sanat plays its own copy, `app/assets/vauhti.mp3`.

## Layout

- `app/` is the deployable unit: `index.html`, `styles/app.css`, `src/*.js`, `assets/vauhti.mp3`. No build step, no runtime dependencies, ES modules loaded directly by `<script type="module" src="src/app.js">`.
- `scripts/serve.mjs` serves `app/` as web root (`node:http`). Flags `--port` (default 8080), `--host` (default 127.0.0.1; use 0.0.0.0 for a device on the LAN). Serves `.js` as `text/javascript`, sends `Cache-Control: no-cache`, returns 403 for paths outside `app/`.
- `tests/unit/` (`node:test`, pure modules) and `tests/e2e/` (Playwright). `package.json` is `"type": "module"`; its only dependency is the dev dependency `@playwright/test` (pinned 1.64.1).
- `.github/workflows/pages.yml` uploads `app/` as the Pages artifact and deploys it on push to `main` and on `workflow_dispatch`. It does not run the tests. The remote `origin` is https://github.com/hakaotu/seikkailut (public).
- `README.md` (Finnish): one-paragraph description and the local run and test commands.
- Commands: `npm run serve`, `npm run test:unit` (`node --test tests/unit/`), `npm run test:e2e` (`playwright test`), `npm test` (both).

## Navigation and the tap rule

Invariant: from a `click` handler (for Matikka's computer-keyboard Enter, a `keydown` handler) to the first `speechSynthesis.speak()` everything is synchronous: no `await`, no `setTimeout`, no dynamic `import()`, no `hashchange`-driven rendering. Registry therefore uses static imports. Reason: iPad Safari must see speech started by the tap. This is unverified on a real iPad. Two exceptions, both speech started from a timer and so not inside a tap: (1) inside `speech.js`, a part with `pauseMs` is spoken after the previous part's `onend`; every part before the first `pauseMs` still is in the tap. (2) A game's auto-advance reading, which the game marks `{ auto: true }` (see Auto-advance).

- Card tap: `history.pushState({fromHome: true}, '', '#/<id>')` then `render(route, {byTap: true})` in the same handler.
- Etusivu / `Etusivulle` button (`goBack`): if `history.state.fromHome`, `history.back()`, else `pushState('#/')`; then renders home synchronously.
- `popstate` and `hashchange` call `render` without `byTap`, so nothing is auto-read. Reload on `#/<id>` also does not auto-read.
- `render` does nothing if the route equals the one shown (`shownRoute`).
- Every route change calls `speech.stop()` first, and `instance.hide()` on the game being left.
- App click and keydown listeners must be attached with `addEventListener`, not `onclick =` or inline onclick: `tests/e2e/helpers.mjs` wraps `EventTarget.prototype.addEventListener` and counts trusted click and keydown listeners on the stack, and the fake `speak` records whether it ran inside one (`gesture.spec.mjs`).
- `autoRead` passed to `show` is `byTap && !resuming`; `resuming` means the view exists and `badgeFor(progress)` is non-null.

## Game contract (full text in `registry.js` header)

A game module is `{ create(ctx) }`. A real game lives in `app/src/games/<id>.js` and default-exports it; `registry.js` imports it statically. `create` is called once per page session, synchronously, on first open; it returns `{ show({autoRead}), hide(), listen() }`. `ctx` has `root`, `question`, `status` (DOM slots), `speech.say(parts, opts?)` with `parts = [{text, rate?, pauseMs?}]` and `opts.auto === true` for a reading the game starts by itself, and `speech.stop()`, and `reportProgress({done, total, finished})`. The front-page badge `Kesken {done}/{total}` shows iff `done >= 1 && !finished`. Rules for ports: no globals or `getElementById` (several views are in the DOM at once); document/window listeners only between `show` and `hide`; no direct `speechSynthesis`; no timer or await between tap and `say`; no control disabled while waiting for speech; assets under `app/assets/` (only `vauhti.mp3` so far; Sanat builds its URL with `new URL('../../assets/vauhti.mp3', import.meta.url)`, so the page path does not matter); `localStorage` keys prefixed with the game id. Only Espanja uses `localStorage`, one key, `espanja.stars`.

If `create` or `show` throws, the shell shows `Peli ei auennut.` with an `Etusivulle` button and marks the view failed; the next open discards it and calls `create` again.

## Speech (`speech.js`)

`createSpeech({synth, Utterance, setTimeout, clearTimeout, startTimeoutMs=2000, maxMs=12000})` returns `{availability, pickVoice, say, stop, onVoicesChanged}`; one instance is shared by all games.

- `availability(lang)`: `unsupported` (no synth/Utterance), `unknown` (empty voice list), `available` (a voice with the same 2-letter prefix), `missing`. `say` refuses `unsupported` and `missing` (reports `failed`; never hands Finnish text to a non-Finnish voice); `unknown` speaks with `u.lang` only.
- `pickVoice(lang)` ranks voices of the language prefix by `[score, exact tag (local > remote), earlier in GOOD_VOICES]`. Score: voice in `AVOID_VOICES` -100; in `GOOD_VOICES[prefix]` (fi: satu, onni; es: monica, jorge, marisol, paulina) 20, plus 30 if its name matches `enhanced|premium|siri` or its `voiceURI` matches `enhanced|premium`; name starting `google` 10; otherwise 0. Names are compared by the part before ` (`, lower case, accents removed.
- `say(lang, parts, onState)` cancels any current call (its callback gets `idle`), then creates all utterances and calls `synth.speak` synchronously for part 0 and the following parts up to the first one with `pauseMs`. `onState(state, reason)` with state `playing | idle | failed`; reasons `unsupported | missing | nostart | error`.
- `pauseMs` is silence before that part; ignored on part 0 and unless a finite number > 0. When the previous part ends, a pause timer of `pauseMs` runs; then the part and the parts after it up to the next `pauseMs` are spoken from the timer.
- A generation counter plus `current` call object make events from superseded calls inert. Utterances are kept referenced until the call ends.
- Start timer 2000 ms: no `onstart` gives `failed('nostart')` and `cancel()`. Cap timer 12000 ms from the first `onstart`, pauses included: gives `idle` and `cancel()`. `onend` of the last part gives `idle`. `onerror` `canceled`/`interrupted` gives `idle`; any other error gives `failed('error')`, except on a part at or after the first `pauseMs` part, where it gives `idle`. A delayed part also has a 2000 ms timer started when it is spoken; if its `onstart` does not come, the call ends `idle` (not `failed`). `stop()` or a new `say()` clears all four timers.
- `voiceschanged` notifies `onVoicesChanged` subscribers; the shell moves `novoice` buttons back to `ready` when the language appears.

Shell side: `failed` sets the button to `novoice` (label `Ei ääntä`) and shows the notice, always when it came from a Kuuntele tap, otherwise once per language per page session. Exception: a `say` with `{ auto: true }` that fails never sets `novoice`, never writes `noVoiceReason` and never shows the notice; it only returns a `playing` button to `ready` (`onSpeechState` in `shell.js`; `speech.js` never sees `auto`). Opening a game whose language is `unsupported`/`missing` also shows it. `Selvä` hides the notice and focuses Kuuntele. The notice text is hard-coded Finnish in `shell.js` (`ADULT_TEXT`).

## Matikka (`games/matikka.js`, `games/matikka-logic.js`)

- Three screens (choose, question, end) are built once in `create` and stay in the DOM; switching toggles `hidden`, so returning from the front page shows what was left. All state is in memory in the instance; nothing is stored, reload gives the choose screen with defaults (Helppo, `+` and `−` on).
- Levels: Helppo (`easy`) shows four option buttons; Keskitaso and Vaikea (`typed: true`) show a keypad. Picking Vaikea turns multiplication on. The last operation toggle cannot be turned off (hint shown). A round is `MAX_QUESTIONS` = 10 problems, generated up front in `newRound`.
- Speech: every handler changes state and DOM first and calls `ctx.speech.say` last, synchronously, with no `pauseMs`. The choose screen is silent on first open; `Aloita`, `Seuraava`, `Pelaa uudelleen`, `Aloita uusi kierros`, an answer, `Katso tulos` and Kuuntele each speak, and so does the auto-advance timer (the only speech not in a tap, passed `{ auto: true }`; see Auto-advance). `show({autoRead})` speaks only on the question screen with the current problem unanswered.
- `reportProgress`: `{done: 0, finished: false}` when a round starts; `{done: answered, ...}` on each answer, not on Seuraava; `{done: 10, finished: true}` on `Katso tulos`. So after the 10th answer and before `Katso tulos` the badge reads `Kesken 10/10`.
- Tap guard: every Matikka button handler is wrapped in `guarded`, which does nothing if `performance.now() - screenChangedAt < 500`; `screenChangedAt` is set by `goTo` (a screen change, not Seuraava). It sets no `disabled` and no timer. The auto-advance timer calls `next` directly, not through `guarded`. Kuuntele and Etusivu belong to the shell and are not guarded. Tests therefore wait with `settle()` (real 550 ms) after a screen change and must not use `page.clock`, which freezes `performance.now()`.
- Keyboard: one `keydown` listener on `document`, added in `show`, removed in `hide`; active only on the question screen of a typed level. Digits and Backspace edit the answer; Enter on a focused button does nothing unless that button is a keypad key, where it means OK/Seuraava (otherwise Seuraava would run twice).
- After an answer, option buttons or keypad keys are `disabled` (answer lock), not while waiting for speech.
- `fitProblem` steps the problem row font from 56 px (40 px under 420 px) down by 4 px while it overflows, to a floor of 36 px (28 px under 420 px); under 420 px, if it still overflows at the floor, it adds `is-wrapped` to the problem element, which lets the row wrap (`flex-wrap: wrap` in `app.css`). It runs in `renderBox`, on `resize` and in `show`.
- Confetti: an `aria-hidden` layer appended to `ctx.root` for scores 7-10 (40 pieces, 3 s; 10/10: 100 pieces, 3.5 s), none under `prefers-reduced-motion: reduce`; the only `setTimeout` in `matikka.js` itself removes it (the auto-advance timer lives in `auto-advance.js`); `hide()` and leaving the end screen remove it.
- Auto-advance: `nextBtn` has class `aa-btn` and holds `fillMarkup('Seuraava', ARROW)`; `matikka.js` creates one controller whose `onAdvance` is `next({auto: true})` (the parameter is named `byTimer` in `next`). See Auto-advance.
- Wrong answers say `Ei ihan.` + `Oikea vastaus on N.` (no retry is offered). End texts depend on score tier (`endTier`: 10 / 7-9 / 0-6); `Täydellinen tulos!` and `Olet matikkamestari!` appear only at 10/10. Stars: `round(score * 5 / answered)`, 0 when nothing is answered.

## Sanat (`games/sanat.js`, `games/sanat-logic.js`)

- Three screens (choose, word, end) are built once in `create` and stay in the DOM; switching toggles `hidden` (`goTo`). All state is in memory; nothing is stored. Defaults: Normaali, Helppo, tavutus off. `settings` is the committed choice, `draft` the choose screen's working copy (`Vaihda` copies `settings` into it).
- A round is `MAX_WORDS` = 10 distinct words from `WORDS` (Normaali, 60 entries) or `HP_WORDS` (Harry Potter, 41), picked by `newDeck`. `renderSlots` toggles class `is-long` on `.sn-slots` for words of 11 letters or more (only `KORPINKYNSI`); at 600 px and wider `app.css` then makes its boxes 52 px (instead of 56, or 60 on iPad portrait) so the word stays on one row. A word's level is fixed when it becomes current (`startWord`): Helppo shows the picture and shuffled letter tiles; Keskitaso shows `?` and an instruction until the word is solved, with tiles; Vaikea has no tiles, only the 29 `ALPHABET` keys (A-Z, Å, Ä, Ö) and `Poista`. Tile shuffles never spell the word (at most 20 reshuffles).
- Word state `result`: `open | first | retry | skipped`. The last letter triggers `check`: right gives `first` (no earlier failed check) or `retry`; wrong keeps all letters, shows `Ei ihan.`, adds to `wrong`. Tapping a filled box removes that letter, `Poista` removes the latest pick, `Aloita alusta` empties the word, `Ohita` sets `skipped`, shows the word and reads `Sana on ...`, then waits for `Seuraava` (no auto-advance).
- `reportProgress`: `done = first + retry + skipped`; `{done: 0, finished: false}` when a round starts, then on each finished word (right or skipped), not on Seuraava; `{done: 10, finished: true}` on `Katso tulos`. After the 10th word and before `Katso tulos` the badge reads `Kesken 10/10`. How the child moved on (tap or timer) does not affect it.
- Scoring: stars `round(a * 5 / done)`, 0 when `done` is 0 (`a` = first-time words). `endTier(a)`: 10 `perfect`, 7-9 `good`, otherwise `done`; the end screen lists first-time, retry and skipped counts (the last two only when 1 or more): `N sana(a) heti oikein`, `Vain 1 sana meni ensin väärin` / `{b} sanaa meni ensin väärin` (the retry row), `N sana(a) ohitettu`. The end speech (`endTexts().speech`) reads those rows as sentences in the same order, skipping the first-time row when `a` = 0 (perfect has its own fixed text); the live-region announcement in `showEnd` uses the same retry-row text. Confetti on `good` (40 pieces, 3 s) and `perfect` (100, 3.5 s), none under `prefers-reduced-motion: reduce`; `goTo` away from the end screen and `hide()` remove it.
- Speech: every handler changes state and DOM first and calls `ctx.speech.say` last, synchronously. The choose screen is silent on first open. `wordSpeech`: the word at rate 0.78, then at 0.52 with `pauseMs: 700`; with tavutus the second part is the syllables at 0.62 (`pauseMs` 700 on the first, 400 on the rest). A letter is said at 0.9; a wrong last letter says the letter, `Ei ihan.` (`pauseMs: 300`), the word at 0.52 (`pauseMs: 700`). `show({autoRead})` reads only on the word screen with an open word. Kuuntele reads the screen it is on.
- `Takaisin sanaan` is shown only when the draft list equals the round's list (a new list needs `Aloita uusi kierros`). `backToWord` decides: level changed and word open: the word restarts (slots cleared, tiles reshuffled, `wrong` kept) and is read in that tap; tavutus changed only and word open: letters kept, hyphens re-rendered, word read; word already finished: no read (a new level applies from the next word); nothing changed: no read. Settings are committed in all cases.
- Victory clip: one `Audio` per instance, created in `create`. On a right word `playVictory()` runs after `say` in the same tap; a 3000 ms timer pauses and rewinds it; `hide()` stops it; Seuraava does not.
- Tap guard: every Sanat button handler (including tiles, keys and filled boxes) is wrapped in `guarded` (ignored within 500 ms of `goTo`); the auto-advance timer calls `next` directly. Kuuntele and Etusivu belong to the shell. Sanat adds no `document`/`window` listeners. Tests use `settle()` after each Sanat screen change.
- `.sn-` classes (not `.accent-btn`/`.ok-btn`, which the notice's strict locators use) are scoped under `.game-view[data-game='sanat']` in `app.css` and listed in the shared pressed/focus selectors.

## Espanja (`games/espanja.js`, `games/espanja-logic.js`)

- Three screens (choose, question, end) are built once in `create` and stay in the DOM; `goTo` toggles `hidden`. State is in memory except the star count. Defaults: direction `fi2es` (Suomi → Espanja), topic `kaikki`. `direction` and `topic` are committed, `draft` and `draftTopic` are the choose screen's copy; `openChoose` resets both drafts from the committed values. Topic and direction are kept while the page lives, not stored. `WORDS` has 79 pairs in seven topics (`tervehdys`, `väri`, `numero`, `eläin`, `ruoka`, `viikonpäivä`, `perhe`); `TOPICS` adds `kaikki` (8 tiles, `role="radio"` in a radiogroup `Aihe`, before the direction cards) and holds each tile's emoji, label and accessible name. `wordsIn('kaikki')` is `WORDS` itself, so the default draw is unchanged. A round has `roundLength(topic)` = `min(10, topic size)` distinct words (`viikonpäivä` 7, `tervehdys` 8, others 10); `round.questions.length` is the length, read through `total()`. The line beside `Aihe` is `topicLine(draftTopic)` (e.g. `Kaikki aiheet: 79 sanaa`, with `, kierroksessa N kysymystä` under 10). Each question's four options (same topic as the word) are drawn in `newRound` and kept.
- Question `result`: `open | right | wrong | skipped`; `counts` gives a, b, c = right, wrong, skipped and `done` = all three. A wrong answer or `Ohita` ends the question (no retry); options are `disabled` after it. `Takaisin kysymykseen` is shown only when the draft direction and draft topic both equal the open round's; `chooseHint` says which of the two differ; `Aloita uusi kierros` replaces `Aloita` while a round is open. The progress bar keeps 10 blocks and hides those from `total()` on.
- `reportProgress`: `{done: 0, total: n, finished: false}` at round start, `done = counts.done` on each answer or skip, `{done: n, total: n, finished: true}` in `showEnd` (`Katso tulos`); the badge reads `Kesken n/n` before it. Tiers: `endTier(a, n)` `a >= n` `perfect`, `a >= starThreshold(n)` `good`, else `done`; confetti on `good` (40, 3 s) and `perfect` (100, 3.5 s), none under reduced motion. The end screen shows `selectionLine` (topic · direction); its buttons are `Pelaa uudelleen` (same topic and direction) and `Vaihda valintoja` (`openChoose`).
- Stars: key `espanja.stars` (the old `es_stars` is not touched), read once in `create` through `loadStars`; an invalid value reads as 0, blocked storage gives `null` and the count then lives in memory from 0. `showEnd` adds one star and saves it at once iff `earnsStar(a, n)` (`a >= starThreshold(n)` = `ceil(4n/5)`: 8 of 10, 7 of 8, 6 of 7) and `round.starGiven` is false, so once per round, on the first end screen. A round not ended with `Katso tulos` gives none. Shown in `ctx.status` (`aria-label` `Tähtiä: n`): stars side by side up to 10, otherwise one star and `× n`.
- Speech (rate 0.9, handler changes state first, `say` last): the card tap and the choose screen are silent. Espanja → Suomi reads the Spanish word when a question appears (`beginRound`, `next`, `show({autoRead})` on an open question); Suomi → Espanja reads nothing then, and Kuuntele on an open question reads the four options with `pauseMs` 500 on options 2-4. After an answer or skip the Spanish word is read in both directions. `spoken` strips `¡ ! ¿ ?` before text reaches the voice. The end screen reads the Spanish phrase (`¡Perfecto!` etc.).
- Auto-advance: `answer` calls `auto.start()` only for a right answer with `index < total() - 1`, after `focusEl(nextBtn)` and before `announce`/`say`; no wait on a wrong answer, `Ohita` or the last question. Cancelled by `next`, `listen`, `openChoose` (`Vaihda`, `Vaihda valintoja`), `beginRound` and `hide`. `next({auto: true})` passes `{ auto: true }` to `say` only in Espanja → Suomi. `rightLive` adds `Seuraava kysymys tulee itsestään.` only when a wait starts.
- Tap guard: handlers are wrapped in `guarded` (ignored within 500 ms of `goTo`); the timer calls `next` directly. `es-` classes in `app.css`.

## Auto-advance (`games/auto-advance.js`)

- After a right answer on items 1-9 Matikka (problems) and Sanat (words), and on questions 1 to n-1 in Espanja (n = `total()`, 10 or a smaller topic's size), the game calls `auto.start()`; after 4000 ms the controller runs `cancel()` then `onAdvance()` (cancel first, so its listeners are gone when the game moves focus). A wrong answer, a skipped Sanat word and the last item start no wait. The game, not the controller, decides when to start and what advancing means.
- Sanat: `.sn-next` has class `aa-btn` and `fillMarkup('Seuraava', ARROW)`; `pick` starts the wait after focus moves to Seuraava; the right-answer announcement ends with `Seuraava sana tulee itsestään.`; `next({auto})` cancels first and returns if the word is still open. Image tap, `listen()`, `openChoose()` (`Vaihda`, `Vaihda valintoja`) and `hide()` cancel.
- `start()` sets `--aa-ms` on the button and adds class `aa-counting` (restarted via an `offsetWidth` read); `app.css` section "Auto-advance" (`aa-` classes, unscoped) draws the fill from `.aa-fill` and, under reduced motion, `.aa-ticks`. The label is generated content from `data-label`, so the button's text and accessible name do not change.
- The wait ends (`cancel()`) on: the timer, `next()` (any caller), `listen()`, `openChoose()`, `hide()` (each game wires these itself), a `focusin` whose target is not the waiting button (Tab, `Selvä`, Kuuntele), and `visibilitychange` to hidden. The two document listeners exist only while a wait runs.
- The timer's `next` passes `{ auto: true }` to `ctx.speech.say`. The shell then ignores a failed reading for Kuuntele and the notice (see Speech), because a browser may refuse speech no tap started.
- Espanja's wiring is in the Espanja section.

## Conventions

- CSS has no `overflow-x: hidden` on `html`/`body`, on purpose, so the layout specs can see sideways overflow.
- Buttons are real `<button>` elements; the Kuuntele button is never `disabled`.
